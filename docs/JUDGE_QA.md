# Emergency AI Platform - Judge Q&A

**Why PostGIS?**
PostGIS allows us to store vehicle and hospital locations as native spatial geometries. This means we can perform highly efficient, index-backed nearest-neighbor searches (e.g., finding the closest ambulance to an SOS coordinate) directly in the database, without pulling thousands of records into the Node server.

**Why Socket.IO?**
In emergency response, polling a server every 5 seconds is too slow and wastes bandwidth. Socket.IO provides a persistent WebSocket connection, enabling sub-second, event-driven telemetry (like GPS updates) to push instantly to the dispatch and hospital dashboards.

**Why both ML and Gemini?**
They solve different problems. Scikit-Learn ML is deterministic and statistical; it excels at predicting ETA times (`eta-v1`) and calculating triage severity (`triage-v1`) based on numeric vitals. Gemini is a Large Language Model; it excels at parsing unstructured human speech (the paramedic's voice notes) and structuring it into JSON. 

**What exactly does ML predict?**
1. **ETA (`eta-v1`)**: Predicts the arrival time in minutes based on distance and priority.
2. **Triage (`triage-v1`)**: Recommends a severity class (Red, Yellow, Green, Black) based on patient vitals (Heart Rate, BP, SpO2, GCS).

**Is the ML clinically validated?**
No. The models are trained on synthetic baseline datasets for this prototype. They are strictly for *decision support*. The final medical decision remains with the qualified paramedic.

**What happens if ML fails?**
The backend catches the failure and degrades gracefully. The UI displays an "ML Unavailable" warning, but the core emergency workflow and manual dispatch/triage buttons remain fully operational.

**What happens if Gemini fails?**
The system alerts the paramedic that voice structuring is offline, allowing them to manually type the clinical summary and submit the report. 

**How do you prevent duplicate SOS requests?**
We use an idempotency key generated by the frontend for each unique SOS session. If the citizen taps "Submit" multiple times, the backend database enforces a unique constraint, preventing duplicate incidents from being created.

**How is ambulance identity secured?**
When the ambulance driver logs in, they receive a JSON Web Token (JWT) containing their specific `ambulanceId` and role. The backend strictly enforces that this token can only update the GPS and status of that specific ambulance.

**How is hospital access secured?**
Similarly, hospital ER staff receive a JWT tied to their `hospitalId`. They can only view incoming incidents routed to their specific facility, ensuring patient data privacy.

**Why is the SOS public?**
To minimize friction during a life-threatening crisis. Forcing a citizen to create an account, verify an email, and log in before reporting a crash costs precious minutes.

**How does realtime synchronization work?**
When a state change occurs (e.g., Ambulance arrives at scene), the backend updates PostgreSQL, then emits a Socket.IO event to specific "Rooms" (e.g., `dispatch-room`, `ambulance-room:AMB-001`). The React frontends listen to these rooms and update their UI state immediately.

**What is the role of the paramedic?**
The paramedic is the clinical authority on the scene. They stabilize the patient, record vitals, review the ML triage recommendation, finalize the severity, and transmit the medical report to the destination hospital.

**Why not let AI make medical decisions?**
AI models can hallucinate or fail on edge cases. In emergency medicine, accountability and human judgment are legally and ethically required. AI serves to reduce cognitive load, not replace the clinician.

**How would this scale across India?**
The Node.js backend is stateless (JWT auth) and can scale horizontally behind a load balancer. PostgreSQL with PostGIS can be sharded geographically. Socket.IO instances can be scaled using a Redis adapter to broadcast events across multiple server nodes.

**How would live traffic/weather be integrated?**
We would replace the synthetic `eta-v1` model inputs with real-time routing APIs (like Google Maps Distance Matrix or OSRM) and ingest weather APIs as feature columns for the ML model.

**How would 108/112 integration work?**
The platform's `/api/dispatch` endpoints can be consumed securely by existing national emergency switchboards via API keys, effectively replacing the public `/sos` frontend with direct machine-to-machine incident creation.

**What is currently simulated?**
The ML training data is synthetic. The hospital and ambulance fleets are seeded dummy data. The ETA model does not use live traffic.

**What is the biggest current limitation?**
The lack of integration with real-time municipal traffic infrastructure and the need for rigorous clinical validation of the ML triage model against real hospital datasets.
